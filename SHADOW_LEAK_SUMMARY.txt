================================================================================
                    MEMORY LEAK FIX - QUICK SUMMARY
================================================================================

PROBLEM: JS Heap keeps growing → Game slows down after 5+ minutes

ROOT CAUSE: Shadow sprite pool was broken
- Sprites were "hidden" but never removed from container
- Container held strong references forever
- Garbage collection couldn't free them
- Each frame: +N MB added to heap

================================================================================
                           WHAT WAS FIXED
================================================================================

FILE: js/sistemaDeIluminacion.js

✅ FIX 1: devolverSpriteSombraAlPool() method
   - NOW: Removes sprite from container BEFORE returning to pool
   - BEFORE: Only set visible=false (sprite stayed in container)
   - CODE: if (sprite.parent) sprite.parent.removeChild(sprite);

✅ FIX 2: Property reset
   - NOW: Resets all sprite properties (alpha, rotation, scale, x, y)
   - BEFORE: Properties kept their old values
   - CODE: alpha=1, rotation=0, scale(1,1), x=0, y=0

✅ FIX 3: Container re-add
   - NOW: When getting sprite from pool, check if it needs to be re-added
   - BEFORE: Assumption sprite was still in container
   - CODE: if (!sprite.parent) containerParaRenderizar.addChild(sprite);

✅ FIX 4: Cross-reference cleanup
   - NOW: Clean up perteneceAFarol reference
   - BEFORE: Cross-reference created memory cycles
   - CODE: sprite.perteneceAFarol = null;

FILE: js/gameObject.js

✅ FIX 5: Removed circular reference
   - BEFORE: spriteSombra.perteneceAFarol = farol;  (unnecessary)
   - AFTER: Commented out - wasn't used anywhere

================================================================================
                           TECHNICAL DETAILS
================================================================================

THE PROBLEM (Object Pooling Done Wrong):

Step 1: Create 1500 shadow sprites
Step 2: Add to container → container.children = [sprite1, sprite2, ...]
Step 3: Every frame: 
  - Show some sprites (visible = true)
  - Hide other sprites (visible = false) 
  - Move to pool array
Step 4: Container still has reference → sprites can't be GC'd
Step 5: Every second: Create new sprites (old ones not freed)
Result: Memory grows forever!

THE SOLUTION (Object Pooling Done Right):

Step 1: Create 1500 shadow sprites (pre-allocated)
Step 2: ONLY add to container when visible
Step 3: Every frame:
  - Get sprite from pool
  - Add to container
  - Render sprite
  - Remove from container (KEY!)
  - Return to pool
Step 4: Sprite not in container → can be GC'd
Step 5: Reuse same sprites over and over
Result: Memory stays constant!

================================================================================
                             KEY TAKEAWAY
================================================================================

Object pooling is great for performance, BUT:
- Must remove objects from visual hierarchy when done
- Must reset all properties/references
- Must re-add to hierarchy when reusing

Before: "Hide and forget"
After: "Remove, reset, re-add"

This ensures the garbage collector can do its job.
